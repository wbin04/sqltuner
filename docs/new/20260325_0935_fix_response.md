# Fix cuối cùng: Phase 2 chỉ 2 cột + Clarification options không có giá trị

## Root cause chính xác

**Phase 2 — 2 cột (3 nguyên nhân kết hợp):**

1. `SCHEMA_PHASE2_SYSTEM_PROMPT` có EXAMPLE dùng domain "tickets/passengers" (flight)
   → Khi user hỏi domain khác, model nhỏ bị confused bởi example → copy hoặc ignore
   → Output sai hoặc chỉ id + created_at

2. `clarification_context` (answers từ user) **chỉ được inject vào Phase 1**,
   **không có trong Phase 2** → Phase 2 không biết user muốn thêm gì

3. `SCHEMA_PHASE2_SYSTEM_PROMPT` dài 2620 chars (~655 tokens) + num_ctx=2048
   → input chiếm ~855 tokens → output còn ~1193 tokens → num_predict=700
   bị cut giữa chừng khi output phức tạp → fallback 2 cột

**Clarification — options chỉ Yes/No:**
`CHAT_SCHEMA_CLARIFICATION_PROMPT` example JSON hardcode options
`["Yes", "No", "Yes, with exceptions"]` → model copy y nguyên → không có
meaningful domain-specific options. Frontend đã hỗ trợ multi-select nhưng
backend không sinh options có ý nghĩa.

## Fix 1 — `SCHEMA_PHASE2_SYSTEM_PROMPT` trong `backend/app/core/prompts.py`

Thay thế toàn bộ. 3 thay đổi:
- Bỏ EXAMPLE domain-specific (flight), thay bằng GENERIC structural example
- Rút ngắn system prompt từ 655 tokens xuống ~250 tokens → giải phóng room cho output
- Instruction rõ hơn: "infer columns FROM the table name and purpose"

~~~python
SCHEMA_PHASE2_SYSTEM_PROMPT = """\
CRITICAL: Output RAW JSON object only. No markdown. No text outside JSON.
Format: {"tables": [ ...array of table objects... ]}

For EACH table in the prompt, generate domain-specific columns based on its name and purpose.

MANDATORY first 2 columns for every table:
{"name": "id", "type": "UUID", "is_pk": true, "is_nullable": false, "default": null}
{"name": "created_at", "type": "TIMESTAMP", "is_pk": false, "is_nullable": false, "default": null}

Then add 4-6 columns that a real database engineer would add for that table's domain.
Infer column names from the table name and purpose description.

Column types to use:
- Names, codes, status, short strings → VARCHAR(255)
- Long descriptions, notes, content → TEXT  
- Counts, quantities, ages → INTEGER
- Prices, amounts, totals → DECIMAL(10,2)
- True/false flags → BOOLEAN
- Date/time values → TIMESTAMP
- References to other tables → UUID (name must end with _id)

Output format (follow this structure exactly):
{"tables": [
  {"name": "TABLE_NAME", "columns": [
    {"name": "id", "type": "UUID", "is_pk": true, "is_nullable": false, "default": null},
    {"name": "created_at", "type": "TIMESTAMP", "is_pk": false, "is_nullable": false, "default": null},
    {"name": "INFERRED_COL", "type": "INFERRED_TYPE", "is_pk": false, "is_nullable": true, "default": null}
  ], "foreign_keys": [
    {"column": "FK_COL_id", "ref_table": "REF_TABLE", "ref_column": "id", "on_delete": "CASCADE"}
  ], "indexes": [
    {"name": "idx_TABLE_COL", "column_names": ["COL"], "unique": false}
  ]}
]}
"""
~~~

    self,
    prompt: str,
    system_prompt: str,
    max_tokens: int,
    read_timeout: float = 120.0,
    json_mode: bool = True,
    num_ctx: int = 2048,        # thêm tham số này
) -> str:
    url = self._build_api_url()
    payload_config = OllamaPayload(
        model=self.chat_model,
        prompt=prompt,
        system_prompt=system_prompt,
        temperature=0.1,
        num_ctx=num_ctx,          # dùng tham số thay vì hardcode 2048
        num_predict=max_tokens,
        json_mode=json_mode,
    )
~~~

## Fix 3 — `CHAT_SCHEMA_CLARIFICATION_PROMPT` trong `backend/app/core/prompts.py`

**Mục tiêu:** Câu hỏi 1 → hỏi về các **thực thể/module** cần có (options là danh
sách domain-specific entities để chọn nhiều). Câu hỏi 2 → hỏi về **quy tắc nghiệp
vụ quan trọng nhất** (Yes/No với context).

Thay thế toàn bộ `CHAT_SCHEMA_CLARIFICATION_PROMPT`:

~~~python
CHAT_SCHEMA_CLARIFICATION_PROMPT = """\
CRITICAL: Output RAW JSON only. No markdown. No text outside JSON.

You are a database architect. The user wants to build a database system.
Generate 2 clarification questions that will most improve the schema quality.

QUESTION DESIGN RULES:
- Question 1: Ask about WHICH ENTITIES/MODULES should be included.
  → options must be a list of 4-6 specific domain entities relevant to the system.
  → User can select multiple options (multi-select).
  → Example for "grocery store": options = ["Inventory management", "Employee management",
    "Promotions & discounts", "Supplier management", "Customer loyalty program", "Delivery tracking"]
  → Example for "flight ticket": options = ["Passenger profiles", "Flight schedules",
    "Payment & refunds", "Seat management", "Baggage tracking", "Loyalty points"]

- Question 2: Ask about the MOST IMPORTANT business rule that changes the schema structure.
  → Must be YES/NO with a clear consequence for schema design.
  → options = ["Yes", "No"] or ["Yes", "No", "Yes, with conditions"]
  → Example: "Should the system track history of changes (e.g. order edits, cancellations)?"
  → Example: "Can one [entity] belong to multiple [other entities] at the same time?"

NEVER ask about: CRUD operations, database engine, number of users.

User's description: "{description}"

Evaluate: is the description clear enough to design a schema without questions?
- If YES (description has 4+ specific entities with clear relationships):
  {{"needs_clarification": false, "questions": []}}
- If NO (vague, missing key entities, or key business rules unclear):
  {{"needs_clarification": true, "questions": [
    {{"q": "Which modules or features should this system include?",
      "options": ["MODULE_1 relevant to {description}", "MODULE_2 relevant to {description}",
                  "MODULE_3 relevant to {description}", "MODULE_4 relevant to {description}",
                  "MODULE_5 relevant to {description}"]}},
    {{"q": "Specific yes/no question about a key business rule in {description}?",
      "options": ["Yes", "No", "Yes, with conditions"]}}
  ]}}
"""
~~~

**Quan trọng:** `{description}` trong `options` của câu hỏi 1 → model sẽ thay thế
bằng domain entities thực tế. Đây là cơ chế để model sinh options domain-specific
thay vì generic.

## Fix 4 — `get_schema_clarification_prompt` trong `backend/app/core/prompts.py`

Hàm hiện tại chỉ replace `{description}` một lần. Cần đảm bảo replace tất cả
occurrences (vì prompt mới có nhiều `{description}` hơn):

Tìm function `get_schema_clarification_prompt` (hoặc `get_chat_schema_clarification_prompt`):

~~~python
def get_schema_clarification_prompt(description: str) -> str:
    """Inject user description vào clarification prompt — replace all occurrences."""
    # Escape description để tránh conflict với format string
    safe_description = description.replace('"', '\\"')
    return CHAT_SCHEMA_CLARIFICATION_PROMPT.replace("{description}", safe_description)
~~~
